# 开发纪律（一页）

开发者：Claude。放行者：项目所有者。设计基线：`docs/design/`（v0.3）。

## 什么时候停下来问你

只有三种：**① 里程碑放行**（M0→M1→…每个阶段结束）**② 要花钱**（任何付费 API / 服务）**③ 不可逆动作**（删除、覆盖非本仓库文件、对外发布、动生产）。其余自动推进，不请示。

## 每个里程碑我交什么

1. **验收清单**：该里程碑退出标准（`11_ROADMAP.md`）逐条打勾，每条附**真实命令输出**（计数、失败项），不写"全部通过"四个字了事。
2. **变更摘要**：改了设计包哪些文件（如有），为什么；新增 / 删除的决策进 `10_DECISIONS.md`。
3. **未做清单**：说明留下了什么、为什么。
4. **下一步建议**：一句话，你只需要说"继续 / 停 / 改方向"。

## 我在里程碑内怎么干

- **先判据后实现**：任何模块先写向量 / fixture / 断言（判据来自设计包），再写代码去过它。判据取自被测对象的测试一律作废。
- **一次一个模块**：顺序 `ledger → contract → identity(占位) → authority → boundary → runtime → builtin plugins → e2e`；每个模块结束跑一次 `npm test`，贴计数。
- **拓扑守卫**：任何新增 import 若与 `02_TOPOLOGY.yaml` forbidden_edges 冲突，停下写 ADR，不绕。
- **设计冲突**：发现设计包内部矛盾或无法实现，提 ADR（`docs/adr/NNNN-*.md`：冲突 / 影响文件 / 是否 blocker / 最小修改），等你一句话；不静默改设计。
- **不扩大范围**：`[RESERVED]` 字段只保证类型与 Schema 存在，不实现语义；`13 §D` 待定项不在里程碑内顺手做。
- **敌意测试不可省**：每个 Provider 角色至少一组 hostile 用例（throw / hang / 垃圾 / 超大 / 改共享对象）。
- **验证走用户入口**：M1 之后每个里程碑的最后一步，我用你会用的方式（命令行跑一个 Agent Spec）从头跑一遍 G1，贴完整输出，而不是只跑单元测试。

## 你需要做的

- 里程碑结束看验收清单，说"继续"或不。
- 想改方向随时说；我不会因为"已经写了很多"而抵触重来。
- 不需要看代码。看不懂的验证是我的责任，我改到你能看懂为止。

## 红线（沿用你的常驻规则）

不编造工具执行；判据不取自被测对象；验证走用户入口；不自作主张换需求 / 换架构；写"必须先 X 才能 Y"前先问该不该有这道闸门。
