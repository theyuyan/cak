# 安装与部署

## 目录约定（全部在 `~/.cak/`）

| 路径 | 内容 | 敏感？ |
|---|---|---|
| `~/.cak/secrets/*.key` | 模型 API key（0600） | **是**，别进仓库/对话 |
| `~/.cak/identity/<agent>/ed25519.{key,pub}` | 每个 agent 的身份（首次自动生成） | 私钥是 |
| `~/.cak/sessions/<name>.sqlite` | 会话账本（事实源，可审计） | 含你的对话与工具结果 |
| `~/.cak/sessions/<name>.history.jsonl` | 会话历史（给模型回喂） | 同上 |
| `~/.cak/plugins/<id>/` | 已装插件（manifest + 代码 + conformance 报告） | 否 |
| `~/.cak/registry/` | 注册表克隆（自动拉取） | 否 |
| `~/.cak/memory.sqlite` | 长期记忆（装了 memory-sqlite 才有） | 是（你的偏好/事实） |
| `~/.cak/sql-query.json` | 数据库连接别名（装了 sql-query 才要） | **是**（可含口令）|

备份 = 备份 `~/.cak/`。删除会话 = 删对应的 `.sqlite`（不可逆）。

## 单机部署（一个人用）

就是《快速开始》：`npm i -g @cak-dev/cli` + 第一次 `cak` 时给 key。`cak` 会在当前目录起一个内核进程（后台常驻，`cak stop` 停），前端只是连上去的客户端。

## 加一个审查 agent
最省事：**同一内核里挂两个 agent**：`cak up --agent coding --agent review`（或运行中 `cak agent add review --session <名字>`）。coding 提交前可以把改动委派给 review（`agent.invoke` → `agent.task`，见手册 07「同一内核里的 agent 互相委派」）。

独立进程（跨机器 / 想让审查方完全隔离）——**目前只有源码路径**（`cak up` 起的内核不对外提供 agent.card/agent.serve；npm 装的用户暂时用不了这条，是已知缺口）：
```bash
# 终端 1（源码目录）：起审查方（只读句柄；只提供 code.review）
cd ~/agent-kernel && npx tsx apps/cak-review/serve.ts --workspace /path/to/repo --port 8790
# 终端 2：coding 接上它
cak up --workspace /path/to/repo --name dev --agent coding --reviewer http://127.0.0.1:8790
```
接上后 coding **提交前必须送审**（结论 `⚖ 审查 …`，跨进程拉对方账本事件验签 `✔ 回执已验`）。
审查方只听 127.0.0.1；跨机器要自己套 TLS/隧道，本项目不做。

## 常驻服务（把一个 agent 挂成 HTTP 服务）

```bash
cak serve <spec.yaml> --port 8791 --ledger ~/.cak/sessions/x.sqlite --key-dir ~/.cak/identity/x [--publish <注册表目录>] [--plugins-dir ~/.cak/plugins]
```
暴露：`GET /card`（名片，含公钥）、`agent.serve` / `agent.receipt` / `handle.mint` / `status`。只听本机。

## 插件目录与注册表

- 安装：`cak add <id> --registry ~/.cak/registry`（或让 agent 装，见插件手册）
- 注册表默认 `https://github.com/theyuyan/cak-registry.git`，cak-code 启动时自动 clone/`pull --ff-only`；离线时用本地副本，`--registry DIR` 指定别处，`--no-registry` 关闭
- 已装插件启动自动装载（全部子进程）；`--plugins-dir DIR` 换目录，`--no-plugins` 关闭

## MCP

工作区放 `.mcp.json`（Claude Code / Cursor 同格式）：
```json
{ "mcpServers": { "memory": { "command": "npx", "args": ["-y", "@modelcontextprotocol/server-memory"] } } }
```
或 `--mcp "memory=npx -y @modelcontextprotocol/server-memory"`（可重复）。首次 `npx -y` 会下载，慢是正常的。`--no-mcp` 关闭。

## 升级

```bash
npm i -g @cak-dev/cli@latest        # 源码用户：cd ~/agent-kernel && git pull && npm install && npm test
```
账本向后兼容（事件只增不改义）；重启时内核会按 spec 补铸新契约的句柄（N-37），已装插件不用重装。

## 卸载

`npm rm -g @cak-dev/cli`（源码用户删 `~/agent-kernel`），再删 `~/.cak/`。后者含你的账本、记忆、密钥，先想清楚。
