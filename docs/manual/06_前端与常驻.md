# 前端与常驻（daemon）：TUI / 桌面 / 网页都是"前端插件"

两种形态，同一套 Host、同一份账本：

| 形态 | 命令 | 适合 |
|---|---|---|
| **内嵌** | `npx tsx ~/agent-kernel/apps/cak-code/cli.ts` | 一个人、一个终端；内核跑在这个进程里 |
| **常驻 + TUI** | 终端 1：`npx tsx ~/agent-kernel/apps/cak-code/daemon.ts --workspace DIR --session NAME`<br>终端 2：`npx tsx ~/agent-kernel/bin/cak.ts front --session NAME`（默认 TUI；`front tty` 是最薄的一行式前端） | 想要流式、单键审批、面板 / 多个界面同时看一个会话 / 桌面程序 |

## 常驻是怎么回事

`daemon` = 内核 + 已装插件 + MCP + 注册表 + 会话账本，常驻一个进程，只听 `127.0.0.1`。它对外只开一个**控制面**：
- `POST /rpc`（JSON-RPC 2.0，信封 `cak/1`）：`kernel.status` · `plugins.list/search/install/registry` · `agents.list/add/remove` · `session.status` · `session.input {text}` · `session.pending` · `session.decide {approvalId, decision: grant|deny|standing}` · `session.handles` · `session.revoke` · `session.report` · `session.tasks` · `session.task`
- `GET /events?since=N`（SSE）：账本事件 + daemon 事件（`daemon.approval.needed` / `daemon.task.result` / `daemon.plugins.reloaded` / `daemon.note`）；`since` 回放，断线重连不丢

**安全**：每个会话一个随机 token，写在 `~/.cak/daemon/<session>.json`（0600，只有你这个系统用户能读）；请求必须带 `x-cak-token`（SSE 用 `?token=`）。同机其他进程或用户拿不到 token，就**不能替你按"允许"**。前端拿到的只是控制面权限——看事件、审批、看状态——**不是能力**，它替不了 agent 干活。

## 切换界面

```
cak front --list                 # 看有哪些：内置 tui / tty / web + 已安装的前端插件（●=默认）
cak front --default <id>         # 设默认
cak front <id> --session NAME    # 直接用某个
cak front web --session NAME     # 打开浏览器界面（daemon 直接提供，网址带 token）
```
界面就是插件：注册表里 `roles: ["frontend"]` 的条目，`cak add` 装（不跑 conformance），`cak front <id>` 用。社区仓库里 `front-plain` 是一个零依赖示例（60 行，照它抄就能写自己的界面）。对 agent 说"我想换个界面"它也会去 `plugin.search`。

TUI 主题：`/theme` 看、`/theme bronze` 切并记住（indigo 靛 / bronze 铜 / moss 苔 / mono 单色），写在 `~/.cak/config.json`。

## TUI（apps/cak-front/tui.tsx）

单栏三段：会话流 / 输入 / 状态线。你说的话前面是靛色 `›`；工具一行一件、灰；回答流式吐字；审批出现时左侧琥珀短竖亮起——**y** 只批这次 · **N** 拒绝 · **a** 本轮全批 · **s** 本会话同类不再问（规则原样显示）；其余时间整屏安静。`↑↓` 历史（跨会话）· `Tab` 补全 `/` 命令 · 粘贴一行带回车=提交 · `/handles`（↑↓ 选、x 撤销、Esc 返回）· `/status /plugins /report /tasks /quit`。`--no-motion` 关掉呼吸点与光标闪。设计稿与三条口径见 `docs/design/18_TUI_DESIGN.md`；实测 100 列与 80 列：框线 ≤100 字符/屏、品牌色 1–2%、状态线无色。

## 前端插件

内置前端 `apps/cak-front/tty.ts` 是最薄的一个：连 daemon、打事件、出现审批时问你 y/N/s、把你打的字发过去。它证明了这层是通的；TUI、桌面（Tauri/Electron）、网页沿同一 API 做即可，内核和插件一行不改。

写自己的前端：`apps/cak-front/client.ts`（`DaemonClient.call / .events`）+ `apps/cak-code/format.ts`（事件 → 一行人话）。发布：注册表条目 `roles: ["frontend"]`、`contracts: []`；`cak add` 对前端不跑 conformance（它没有契约），拉代码构建即装；`cak front <id>` 启动。

## 现状（诚实）

- 有：daemon、控制面 API、SSE、token；内置三种界面（TUI / tty / web）+ 已安装前端插件切换；TUI 四套主题；流式
- 网页界面在无头 Chromium 里真渲染验证过（审批块/diff/结果/状态线）；TUI 在真 PTY 里逐字驱动验证过
- 没有：桌面壳（Tauri/Electron 套网页界面即可，等 L3 之后）
- 一个内核进程可挂多个 agent（各自会话）；`session.*` 与 `/events` 用 `agent` 参数选，前端 `--agent`
