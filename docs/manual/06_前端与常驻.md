# 前端与常驻（daemon）：TUI / 桌面 / 网页都是"前端插件"

两种形态，同一套 Host、同一份账本：

| 形态 | 命令 | 适合 |
|---|---|---|
| **内嵌** | `npx tsx ~/agent-kernel/apps/cak-code/cli.ts` | 一个人、一个终端；内核跑在这个进程里 |
| **常驻** | 终端 1：`npx tsx ~/agent-kernel/apps/cak-code/daemon.ts --workspace DIR --session NAME`<br>终端 2：`npx tsx ~/agent-kernel/bin/cak.ts front --session NAME` | 想换界面 / 多个界面同时看一个会话 / 桌面程序 |

## 常驻是怎么回事

`daemon` = 内核 + 已装插件 + MCP + 注册表 + 会话账本，常驻一个进程，只听 `127.0.0.1`。它对外只开一个**控制面**：
- `POST /rpc`（JSON-RPC 2.0，信封 `cak/1`）：`session.status` · `session.input {text}` · `session.pending` · `session.decide {approvalId, decision: grant|deny|standing}` · `session.handles` · `session.revoke` · `session.report` · `session.tasks` · `session.task`
- `GET /events?since=N`（SSE）：账本事件 + daemon 事件（`daemon.approval.needed` / `daemon.task.result` / `daemon.plugins.reloaded` / `daemon.note`）；`since` 回放，断线重连不丢

**安全**：每个会话一个随机 token，写在 `~/.cak/daemon/<session>.json`（0600，只有你这个系统用户能读）；请求必须带 `x-cak-token`（SSE 用 `?token=`）。同机其他进程或用户拿不到 token，就**不能替你按"允许"**。前端拿到的只是控制面权限——看事件、审批、看状态——**不是能力**，它替不了 agent 干活。

## 前端插件

内置前端 `apps/cak-front/tty.ts` 是最薄的一个：连 daemon、打事件、出现审批时问你 y/N/s、把你打的字发过去。它证明了这层是通的；TUI、桌面（Tauri/Electron）、网页沿同一 API 做即可，内核和插件一行不改。

写自己的前端：`apps/cak-front/client.ts`（`DaemonClient.call / .events`）+ `apps/cak-code/format.ts`（事件 → 一行人话）。发布：注册表条目 `roles: ["frontend"]`、`contracts: []`；`cak add` 对前端不跑 conformance（它没有契约），拉代码构建即装；`cak front <id>` 启动。

## 现状（诚实）

- 有：daemon、控制面 API、SSE、token、内置 tty 前端、前端角色；两进程真跑过（daemon 里的 DeepSeek 干活，前端只按 `s`）
- 没有：正式的 TUI（面板/流式/鼠标）、桌面壳。它们现在有了可以插的插座
- 一个 daemon 一个会话；多会话 = 多个 daemon（各自端口、各自 token）
