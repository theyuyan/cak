# 插件手册：装插件、写插件、发布到注册表

## 一、装插件

### 方式 A：让 agent 替你装（推荐给不想碰终端的人）
在 cak-code 里直接说你想要什么能力：
```
› 我想让你能查数据库
```
它会 `plugin.search` 找到候选、用人话解释、`plugin.install`（**问你一次**）、装完自动热加载，再按插件的 setup 说明引导你配置。口令类内容它会让你自己填进文件，不会在对话里要。

### 方式 B：命令行
```bash
npx tsx ~/agent-kernel/bin/cak.ts add <插件id> --registry ~/.cak/registry [--install-dir ~/.cak/plugins]
```
`cak add` 是 **trust-but-verify**：拉代码 → 构建 → **在你本机复跑一致性测试** → 全过才写入 `~/.cak/plugins/<id>/`（tier T1）；有一项不过就不装并列出哪项。它不信任任何人自报的测试报告。

### 插件的权限
插件契约按副作用分：`read`/`none` 免审批，其余默认审批。**插件本身拿不到任何权限**——它只是"能干活的人"，让不让干、干到什么范围，由句柄 caveat 决定；第三方插件一律子进程。

## 二、写插件（TypeScript）

```bash
npm create @cak-dev/plugin my-tool -- --contract file.read --contract-version 1.1.0 --digest sha256:…   # 注意 npm create 后的 --；digest 从注册表 contracts/ 抄
cd my-tool && npm install && npm run build && npm test && npm run conformance
# 新契约：写 contracts/<name>@1.json → cak digest contracts/<name>@1.json --write（算 digest 并顺手检查 additionalProperties:false）→ 填进 provider.ts
# 装进本机试用（不经注册表）：cak add ./my-tool [--contract <name> --args '<sampleArgs>']  → 起内核就能用；运行中的内核下一句话就能看到新工具
```
（模板默认依赖 npm 上的 `@cak-dev/sdk@^0.3.0`；想用本地改过的 SDK：`--sdk file:~/agent-kernel/sdk/cak-dev-sdk-0.3.0.tgz`，tarball 用 `cd ~/agent-kernel/sdk && npm pack` 生成。）

你只写两个方法：
```ts
export class MyToolProvider implements CapabilityProvider {
  readonly id = 'my-tool';
  listImplementations() { return [{ providerId: this.id, contract: CONTRACT, priority: 50 }]; }
  async execute(inv: AuthorizedInvocation, ctx: ProviderCallContext): Promise<ProviderExecuteResult> {
    // inv.args 已过内核验证与句柄检查；按契约 outputSchema 返回 { output } 或 { error: {code,message,retryable} }
  }
}
```
同一份代码两种形态：进程内 `new MyToolProvider()` 注册；子进程 `servePlugin(new MyToolProvider(), { pluginId, version, kernelCompat })`。

**规矩**：
- 契约声明 `idempotent: true` 时，输出里**不能有每次都变的字段**（耗时、时间戳、created…），conformance 会拿两次结果比对——这条已经拒装过两次
- 输出必须合契约 outputSchema（`additionalProperties: false` 很严）
- conformance 过 ≠ 逻辑对：给插件写自己的测试（`npm test`）
- 用现成契约还是新契约？能用现成的就用（模型认识、句柄规则现成）；新契约写成 JSON 放到**注册表仓库** `cak-registry/contracts/community/<name>@1.json` 提 PR（内核不必发版：`cak add` 的一致性测试与宿主 compose 都会从 `~/.cak/registry/contracts/**` 读，见 N-50）；实验阶段用 `x.` 命名空间。本地开发时用 `cak conformance … --contracts <你的契约文件或目录>` 先验
  - 契约文件字段：name / version / description / inputSchema / outputSchema（都 `additionalProperties:false`）/ permissions / sideEffects（none|read|write|external）/ idempotent / defaultTimeoutMs / async / schemaDigest（`sha256(JCS({name,version,inputSchema,outputSchema,sideEffects,idempotent,permissions}))`，`cak-registry/scripts/validate.mjs` 会校验）

## 三、写插件（Python）

```python
from cak_sdk import serve_plugin, ok, error
class P:
    id = "my-py"
    def list_implementations(self): return [{"providerId": self.id, "contract": {...}, "priority": 50}]
    def execute(self, call, ctx): return ok({...})
serve_plugin(P(), plugin_id="my-py", version="0.1.0", kernel_compat="^0.3.0")
```
零依赖；`sdk-python/` 里有完整示例。验证同一条命令：`cak conformance --subprocess "python3 my_py.py" --contract <name> --args '{…}'`。其他语言：按 `docs/design/19_PLUGIN_WIRE_PROTOCOL.md` 的 `cak/1` 协议（JSON-RPC 2.0 over NDJSON：hello / health / shutdown / capability.execute / cancel）自己实现即可，内核不看语言。Python 插件要被 `cak add` 装到别处运行：把 `cak_sdk/` 目录一起放进插件仓库（PyPI 未发），或 `sys.path` 指向它。

## 四、发布到注册表

1. 代码放一个 git 仓库（社区 monorepo `theyuyan/cak-plugins/plugins/<id>` 或你自己的）
2. 在 `cak-registry/index.json` 加条目：
```json
{ "id": "my-tool", "version": "0.1.0", "kernelCompat": "^0.3.0", "license": "Apache-2.0",
  "description": "一句人话说明（会给小白看）", "keywords": ["中文关键词", "english"],
  "install": { "type": "git", "url": "https://github.com/you/repo.git", "ref": "main", "subdir": "plugins/my-tool" },
  "entrypoint": { "type": "subprocess", "command": "node", "args": ["dist/main.js"] },
  "contracts": [{ "name": "file.read", "version": "1.0.0", "sampleArgs": { "path": "README.md" } }],
  "setup": "装后要做什么（没有就写无需配置）" }
```
`build` 缺省 = `npm install` + `npm run build`；Python 等写 `"build": []`。
3. `npm run validate` 过 → 提 PR。注册表 CI 会重跑校验；用户那边 `cak add` 时还会再跑一次 conformance。

## 技能（skill）：流程说明书也是插件（N-52）
Claude Code 里的 skills 在这里长这样：**技能 = 一个目录 + `SKILL.md`（frontmatter：name / description / requires）+ 可选附件**，只给模型看，不含可执行代码。
- 装 `skills` 插件（`cak add skills` 或对 agent 说"我要技能库"）→ 宿主自动把 `skill.list` 挂成上下文源：模型每轮看到"技能清单"（名字 + 何时用），对得上就 `skill.read` 读全文按流程做，每次读取进账本。
- 技能从哪来：`~/.cak/skills/<name>/`（自己写）· `<工作区>/.cak/skills/<name>/`（跟项目走）· 注册表条目 `roles: [skill]`（`cak add skill-weekly-report`；tier **T0**，只 clone 不跑 conformance，带可执行入口的会被拒装）。
- 现成的：`skill-cak-plugin-author` / `skill-weekly-report` / `skill-incident-triage`。写自己的：照 cak-plugins 仓库里 `skills/weekly-report/SKILL.md`（本机若 clone 在别的目录名下，以仓库为准）。
- 边界：技能说"跑 X"，agent 也得拿自己持有的句柄去调、照样过审批——技能不提权。
