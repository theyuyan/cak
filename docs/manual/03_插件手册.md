# 插件手册：装插件、写插件、发布到注册表

## 一、装插件

### 方式 A：让 agent 替你装（推荐给不想碰终端的人）
在 cak-code 里直接说你想要什么能力：
```
› 我想让你能查数据库
```
它会 `plugin.search` 找到候选、用人话解释、`plugin.install`（**问你一次**）、装完自动热加载，再按插件的 setup 说明引导你配置。口令类内容它会让你自己填进文件，不会在对话里要。

### 方式 B：命令行
```bash
npx tsx ~/agent-kernel/bin/cak.ts add <插件id> --registry ~/.cak/registry [--install-dir ~/.cak/plugins]
```
`cak add` 是 **trust-but-verify**：拉代码 → 构建 → **在你本机复跑一致性测试** → 全过才写入 `~/.cak/plugins/<id>/`（tier T1）；有一项不过就不装并列出哪项。它不信任任何人自报的测试报告。

已有插件（注册表 `theyuyan/cak-registry`）：

| id | 能力 | 装后要做什么 |
|---|---|---|
| `http-fetch` | 抓网页（GET/HEAD、HTML→文本、拒绝内网地址） | 无 |
| `sql-query` | 只读 SQL（SQLite / Postgres），连接别名制 | 建 `~/.cak/sql-query.json`：`{"connections":{"demo":{"driver":"sqlite","file":"/绝对路径.sqlite"}}}`；Postgres 用 `{"driver":"postgres","urlEnv":"PG_URL"}` |
| `memory-sqlite` | 长期记忆（写入 + 自动检索） | 无 |
| `py-summarize` | 文本摘要（Python 写的示例） | 需本机 python3 |
| `doc-read` | 读 PDF / Word / Excel / CSV（表格给 markdown + 结构化），只在工作区内 | 无 |
| `browser` | 真浏览器（Playwright/Chromium）：打开、读快照、按 ref 点击/输入、截图；拒内网 | 无（安装时下载 Chromium ~150MB） |
| `github` | GitHub 只读查询（免审批）+ 建 issue / 评论（审批） | 令牌：`GITHUB_TOKEN` / `~/.cak/secrets/github.token` / 本机 `gh auth login` |
| `pkg-info` | 查 npm / PyPI 最新版本、发布日期、README（写代码前确认版本） | 无 |
| `notify` | 发通知到 Slack / 企微 / 钉钉 / 通用 webhook（渠道别名制） | 建 `~/.cak/notify.json`，webhook 地址写进 `~/.cak/secrets/` 文件 |
| `web-search` | 网页搜索（Brave / Tavily / SearXNG 三选一；**作者无 key 未联网真测**） | 建 `~/.cak/web-search.json`（engine + keyFile 或 url），key 写进 `~/.cak/secrets/` 文件 |

### 插件的权限
插件契约按副作用分：`read`/`none` 免审批，其余默认审批。**插件本身拿不到任何权限**——它只是"能干活的人"，让不让干、干到什么范围，由句柄 caveat 决定；第三方插件一律子进程。

## 二、写插件（TypeScript）

```bash
npx create-cak-plugin my-tool --contract file.read --digest sha256:…   # digest 从注册表 contracts/ 抄
cd my-tool && npm install && npm run build && npm run conformance
```
（未发 npm 前：`node ~/agent-kernel/packages/create-cak-plugin/bin/create.mjs my-tool --contract … --sdk file:~/agent-kernel/sdk/cak-sdk-0.3.0.tgz`，tarball 用 `cd ~/agent-kernel/sdk && npm pack` 生成。）

你只写两个方法：
```ts
export class MyToolProvider implements CapabilityProvider {
  readonly id = 'my-tool';
  listImplementations() { return [{ providerId: this.id, contract: CONTRACT, priority: 50 }]; }
  async execute(inv: AuthorizedInvocation, ctx: ProviderCallContext): Promise<ProviderExecuteResult> {
    // inv.args 已过内核验证与句柄检查；按契约 outputSchema 返回 { output } 或 { error: {code,message,retryable} }
  }
}
```
同一份代码两种形态：进程内 `new MyToolProvider()` 注册；子进程 `servePlugin(new MyToolProvider(), { pluginId, version, kernelCompat })`。

**规矩**：
- 契约声明 `idempotent: true` 时，输出里**不能有每次都变的字段**（耗时、时间戳、created…），conformance 会拿两次结果比对——这条已经拒装过两次
- 输出必须合契约 outputSchema（`additionalProperties: false` 很严）
- conformance 过 ≠ 逻辑对：给插件写自己的测试（`npm test`）
- 用现成契约还是新契约？能用现成的就用（模型认识、句柄规则现成）；新契约放 `contracts/builtin/` 提 PR，或先用 `x.` 实验命名空间

## 三、写插件（Python）

```python
from cak_sdk import serve_plugin, ok, error
class P:
    id = "my-py"
    def list_implementations(self): return [{"providerId": self.id, "contract": {...}, "priority": 50}]
    def execute(self, call, ctx): return ok({...})
serve_plugin(P(), plugin_id="my-py", version="0.1.0", kernel_compat="^0.3.0")
```
零依赖；`sdk-python/` 里有完整示例。验证同一条命令：`cak conformance --subprocess "python3 my_py.py" --contract <name> --args '{…}'`。其他语言：按 `docs/design/09` 里的 `cak/1` 协议（JSON-RPC 2.0 over NDJSON，5 个方法）自己实现即可，内核不看语言。

## 四、发布到注册表

1. 代码放一个 git 仓库（社区 monorepo `theyuyan/cak-plugins/plugins/<id>` 或你自己的）
2. 在 `cak-registry/index.json` 加条目：
```json
{ "id": "my-tool", "version": "0.1.0", "kernelCompat": "^0.3.0", "license": "Apache-2.0",
  "description": "一句人话说明（会给小白看）", "keywords": ["中文关键词", "english"],
  "install": { "type": "git", "url": "https://github.com/you/repo.git", "ref": "main", "subdir": "plugins/my-tool" },
  "entrypoint": { "type": "subprocess", "command": "node", "args": ["dist/main.js"] },
  "contracts": [{ "name": "file.read", "version": "1.0.0", "sampleArgs": { "path": "README.md" } }],
  "setup": "装后要做什么（没有就写无需配置）" }
```
`build` 缺省 = `npm install` + `npm run build`；Python 等写 `"build": []`。
3. `npm run validate` 过 → 提 PR。注册表 CI 会重跑校验；用户那边 `cak add` 时还会再跑一次 conformance。
