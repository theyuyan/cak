# 安全模型（用户版）

一句话：**agent 想干什么都得持"句柄"，句柄上写着能干什么、干到哪、要不要问你；每一步都记在不可篡改的账本里。**

## 它保护什么

| 威胁 | 机制 | 你怎么看见 |
|---|---|---|
| agent 越权（读工作区外的文件、跑不该跑的命令、调不该调的 agent） | 两道墙：句柄 caveat 在执行前验证（内置 file.* 的路径墙目前在 Provider 一层：字面路径 + 符号链接真实路径都判，越界 = `CAPABILITY_ERROR path … escapes workspace`；插件契约里 `path/target/outPath/localPath` 入参有句柄级 `args.match` 墙 = `CAVEAT_VIOLATION`，连审批都不进） | 账本 `invocation.failed`（Provider 墙）/ `invocation.denied`（句柄墙） |
| 模型胡编参数 | 执行前按契约 inputSchema 校验 = `ARGS_INVALID` | 同上 |
| 危险操作未经你同意 | 写/命令/提交/装插件/MCP 默认 `requires-approval`；审批绑定**这一次调用的摘要**，改参数即失效 | 终端提示；账本 `invocation.awaiting → grant.issued/denied` |
| "始终允许"变成无限授权 | 不是关审批，是新铸一枚**窄**句柄（同目录/同命令前缀/同站点/同工具），有到期，可撤 | `/handles` `/revoke` |
| 插件是坏的 | 第三方插件一律子进程；装前本机复跑 conformance；契约 digest 不符装配期直接拒 | `cak add` 输出 |
| 另一个 agent 冒充/篡改结论 | Ed25519 身份；跨 agent 调用带签名回执，Merkle 根覆盖对方全部事件 | `✔ 回执已验` / `✗ 回执验证失败` |
| 事后抵赖 | 账本是哈希链、只增不改；每条含主体链、参数、审批、结果摘要 | sqlite 直接查 |
| 口令进上下文 | 模型 key 在文件、连接口令在插件配置；插件按别名取；对话里从不要口令 | 设计如此，代码可查 |

## 它不保护什么（老实说）

- **不防你自己**：你按了 `y` / `a` / `--yes`，就是授权了。`--yes` 请只在你信得过的脚本任务里用
- **不防模型的"聪明"绕路**：它拿不到你没给的句柄，但拿到的句柄它会想尽办法用（例如用 `shell.exec` 去 `cat` 一个工作区外的文件——这是 shell 句柄的权限；要收紧就在审批时拒绝、或用 `s` 建窄句柄、或改 spec 里 shell 的 caveat）
- **不做网络安全**：HTTP 只听 127.0.0.1、没有 TLS；控制面（daemon）有每进程随机 token（`~/.cak/daemon/<name>.json`，0600；`x-cak-token` 头或 `?token=`），无 token 401；跨机器部署要你自己加隧道
- **不审计插件代码**：conformance 证明"合规"，不证明"无恶意"；T1 的意思就是"本机测过、没人审过"
- **账本本身是明文**：里面有你的对话与工具结果；备份、分享账本前想清楚
- **没做过第三方安全审计**

## 建议的习惯

- 工作区就是边界：别把 `--workspace` 指到 `~`
- 长任务用 `s` 放开确切需要的那一类，别用 `a`
- 每隔一阵 `/handles` 看看常设句柄，不要的撤掉
- 换机器/给别人看之前，`~/.cak/secrets`、`~/.cak/identity`、`~/.cak/sql-query.json` 三样别带

## 插件与个人数据（2026-08-19 加固）
- 已装插件默认给每个 agent 都用；agent 配置（`~/.cak/agents/<name>.yaml`）顶层可写 `plugins: { include: [id…] }` 或 `{ exclude: [id…] }` 只给/不给某些插件，`plugins: { approveReads: true }` 让所有读类调用也走审批。
- 注册表条目标了 `sensitiveReads`（邮件、日历、剪贴板、远端主机、容器）的插件，读类契约默认也要审批——「编程助手不问一声就读走剪贴板」是测试员实测抓到的，现在会问。
- 账本与会话历史文件 0600；`session.decide` 只认 grant / deny / standing（`approve` 是 grant 别名），别的值一律报错不放行。
