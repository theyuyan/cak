# 17 · 成熟度路线：从"能用"到"相对成熟"（2026-08-18）

> 用户目标：**做一个相对成熟的内核和插件生态**，不是急着发 alpha。
> 那就把"成熟"写成可以打勾的门。每一级都是"做到了才算"，不按时间算。

## 现在在哪：L1（本机可用）

> 08-19 形状对齐（N-47）：`cak up` 空内核 + `cak agent` 配置 + 控制器/后端可作插件装 —— 用户主线「装内核→装插件→搭 agent」字面成立。

已达成：146 测试 / 接口面冻结 + 守卫 / 5 轮 dogfood 内核零改动 / 4 个插件 + 注册表 + `cak add` 从 git 源装 / TS+Python 两套 SDK 同一协议 / 两个 agent 跨进程互调回执可验 / 用户手册 6 篇（快速开始照着从零跑通）。
诚实缺口：**只有作者一个人用过、只在一台 Intel Mac、只有 DeepSeek 一个真模型、全部发生在 2 天内**。

## L3 · 可交给团队（目标：不止一个人、不止一台机器）

| 门 | 判据 |
|---|---|
| 外部插件 | ≥ 3 个**不是作者写的**插件过 conformance 进注册表 |
| 服役时间 | 内核接口面连续 ≥ 30 天零 Stable 改动（守卫为证）|
| 跨机 | 两台机器上的 agent 经网络互调（TLS/鉴权在部署层落地）、回执互验 |
| 发现 | 托管注册表 R2（不用 clone Git 就能 `cak add`）+ 名片发布/查找走网络 |
| 安全 | 至少一次外部（非作者）安全评审，发现项闭环 |
| 运维 | 账本归档/压缩、会话导出、诊断命令 `cak doctor`（☑ 已有） |

## L4 · 可交给普通用户

| 门 | 判据 |
|---|---|
| 零终端 | 桌面/网页外壳：装、配、审批全图形化；小白路径（agent 替装）在外壳里可用 |
| 多模型/多后端 | ≥ 3 家模型后端真跑，切换不改任务 |
| 结算 | pricing → 账单 → 至少一种真实支付/记账对接（这一块用户当初说"还没想到"，留到这里再定）|
| 稳定承诺 | 1.x 语义化版本、弃用政策、安全公告渠道 |
