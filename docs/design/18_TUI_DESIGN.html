3 · 身份方向三选一；品牌色只在结构，所以差别在"那一点点"上——但要能一眼认出这是 cak

A · 靛 推荐

提示符与光标靛青，审批琥珀，错误朱红，内容两级灰。与你已有产品（AI 门户的青墨+琥珀、MindVault 的铜、CLI 速查的琥珀/绿）都不撞。"契约、印信、账本"的冷静感。

B · 铜

暖调，和 MindVault 一脉。缺点：审批色只能改用靛，"要你处理"反而不够跳；且与你另一产品身份重叠。

C · 苔

绿系提示符很多 CLI 在用（Codex 也是绿），辨识度最弱。列出来只为对照。

配色全部走 token（`ui/theme.ts` 一处），换方向改一处。终端 256 色回退表一并给出。

5 · 动效三处，且都有"不动"的理由

  • 思考呼吸点 ◌ ◍ ●，400ms 一拍，灰色——告诉你"它活着"，不抢眼
  • 流式吐字：模型的回答逐字出现，光标用品牌色；工具行不流式（一行一件事）
  • 审批区出现/收起：出现时左侧琥珀短竖亮起、输入行提示切成"y/N/a/s"；决定后整块回灰、提示复原。不滑不弹

不做：进度条、彩色 logo、边框动画、打字机式工具输出。prefers-reduced-motion 对应终端里的 --no-motion：呼吸点变静态、流式改整段。

6 · 怎么验收不是我看截图说好

  1. 真驱动：用现有的 drive 脚本走六个状态 × 三类任务（读 / 改 / 跑命令 / 装插件 / 审查），用真实内容
  2. 量三条口径：抓屏数框线字符、数彩色字符占比、检查常驻线是否有色
  3. 80 列 / 120 列 / 200 列各跑一遍，窄屏不挤不断行错位
  4. 你亲手用一轮，说哪里别扭——那是最重要的输入

技术：Ink（React 渲染终端）+ 现有 daemon 控制面 + 新增 `daemon.model.delta` 流式事件（内核 `BackendRequest.onDelta` 只增不改）。前端不含内核。
